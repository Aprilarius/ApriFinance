# Личный облачный обмен — версия 1.0, сборка 20

Ручной обмен и включаемый отдельно автоматический режим текущей сессии: Настройки → Открыть облачный обмен. Устройства обращаются к Supabase напрямую, домашний сервер не нужен. Передаётся целая зашифрованная база с чеками, целями, долгами и настройками анализа. Независимые изменения объединяются по общей предыдущей версии; конфликт требует выбора одной полной базы. Запуск новых обменов в фоне и передача отдельных вложений пока не реализованы.

Клиент и алгоритм проверены локальными тестами, включая три независимых базы и правки во время отправки. Схема выполнена в новом Supabase; транзакционные SQL-проверки подтвердили изоляцию владельцев, запрет прямой и анонимной записи, отказ старому клиенту и конфликт версий. Тестовые аккаунты не сохранялись. Настоящий вход по HTTP и обмен трёх физических устройств ещё требуют проверки. Первое подключение проверяйте на вымышленных данных.

## Настройка проекта

1. Создайте личный проект в [Supabase](https://supabase.com/dashboard). В SQL Editor выполните файл [supabase.sql](supabase.sql) в новом проекте или для обновления этой же схемы. Он создаёт таблицу и функцию, не изменяя чужие таблицы.
2. Создайте собственный аккаунт Email/Password в управлении пользователями проекта. Используйте подтверждённый адрес и пароль. Для личного приложения отключите публичную регистрацию. Регистрация, CAPTCHA, MFA и восстановление пароля внутри приложения этой версии не добавлены.
3. Скопируйте HTTPS URL проекта и **publishable** ключ из Connect / API Keys. В приложение вводится публичный ключ, а не secret/service_role. [Официальная инструкция по ключам](https://supabase.com/docs/guides/getting-started/api-keys).
4. В приложении откройте Настройки → Открыть облачный обмен. Введите URL, публичный ключ, email и пароль аккаунта. Нажмите «Войти».
5. Придумайте отдельный пароль зашифрованной копии из 10–256 символов, повторите и сохраните его отдельно. Нажмите «Проверить изменения», изучите результат, затем «Выполнить обмен». Для уже созданной копии нужен её прежний пароль. Изменение пароля шифрования этой версией не поддерживается.
6. На втором и третьем устройствах используйте тот же проект, аккаунт и пароль копии. Пустая база получает облачные данные. Если на обоих устройствах уже есть независимые базы, приложение потребует явного выбора исходной версии. После этого новые автономные изменения можно объединять.

URL поддерживается в форме `https://project.supabase.co`, без дополнительных путей, порта и перенаправлений. Self-hosted и custom domain пока не поддерживаются. После перезапуска приложения войдите снова: пароль аккаунта, пароль копии, access/refresh-токены на диск не записываются. Сохраняются только URL и публичный ключ.

## Автоматический режим в текущей сессии

После входа включите «Автоматический обмен в этой сессии», затем введите пароль копии и выполните один успешный ручной обмен. До этого шага автоматическая отправка не запускается. Пароль останется только в памяти; его не нужно повторно вводить при каждом обмене внутри этой сессии.

Новые локальные изменения запускают обмен после паузы 2 секунды. Возвращение в приложение запускает проверку примерно через секунду; пока приложение открыто, новые облачные изменения проверяются раз в минуту. Сетевые ошибки повторяются с задержками 5, 15, 60 и затем 300 секунд. Интервалы приблизительные и зависят от планировщика ОС. Параллельные попытки не создаются.

При сворачивании или потере активного состояния новые попытки не запускаются. Начавшаяся запись может завершиться, чтобы корректно подтвердить серверную версию. После возвращения проверка продолжается. Режим работает при открытом приложении, не является фоновой службой и не гарантирует непрерывный обмен при выключенном устройстве.

Конфликт, восстановление резервной копии, истечение сессии или ошибка расшифровки останавливают автоматический режим. На основном экране появляется «Обмен приостановлен» с кнопкой перехода к проверке. Выбор версии требует прежнего явного подтверждения. После успешного ручного решения автоматический режим может продолжить работу; после нового входа его нужно включить заново.

Выключение переключателя удаляет сохранённый в памяти пароль автоматического режима и отменяет таймер. Выход из аккаунта и закрытие процесса также завершают сессию. Закрытие только экрана облачных настроек оставляет включённый режим работать в основном приложении. Ручной предпросмотр временно приостанавливает автоматические изменения, чтобы данные не менялись во время выбора.

По сети по-прежнему передаётся полная зашифрованная база с вложениями; ежеминутная проверка может расходовать заметный трафик. Постоянная сессия и защищённое системное хранение ключей пока не добавлены.

## Что делать при конфликте

Для противоречащих изменений одной записи показаны локальный и облачный варианты. Между связанными записями также возможен конфликт: например, удаление расхода и возврат к нему на другом устройстве; оплата одного периода на двух устройствах; архивирование пустого счёта одновременно с новым списанием.

После флажка подтверждения можно использовать полную локальную или облачную версию. Выбор распространяется на всю базу. Вытесняемая версия сохраняется в зашифрованную защитную копию до замены. Если сохранить её нельзя, соответствующая замена не выполняется. При сетевой гонке или изменении локальных данных повторите проверку.

Все защитные версии доступны в Настройки → Все защитные копии. Можно выгрузить нужный файл .mfin и открыть через обычное восстановление с предпросмотром. Для каждой копии нужен пароль, действовавший при её создании. Если нужна информация из обеих конфликтующих версий, сохраните обе копии и перенесите недостающие записи вручную: редактор выбора отдельных конфликтующих записей ещё не реализован.

## Совместимость и данные анализа

Обновите все устройства до сборки 20 или новее. RPC `put_finance_snapshot_v2` включает данные анализа; старый RPC отклоняет запись, чтобы прежний клиент не удалил новые настройки. Независимые цели и долги объединяются по ID; пороги, метки и алиасы — по ключам. Разные правки одной записи требуют выбора полной версии. Дата подтверждения внешней резервной копии, разрешения уведомлений и секреты остаются на устройстве. Пароли и токены хранятся только в памяти до выхода или завершения приложения. Истёкшая сессия требует повторного входа.

## Устройство обмена

- В облаке хранится одна зашифрованная копия на аккаунт. Финансовые таблицы, имена чеков и документы находятся внутри AES-256-GCM-конверта существующего формата .mfin. Серверу доступны размер копии, аккаунт, номер версии и время записи.
- Таблица закрыта RLS; чтение ограничено `auth.uid() = owner_id`. Запись разрешена только через функцию с проверкой владельца и ожидаемой серверной версии. Её блокировка сериализует запись, в том числе создание первой версии. [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [вызов RPC](https://supabase.com/docs/reference/dart/rpc).
- Последняя общая зашифрованная версия сохраняется в отдельной локальной таблице sync_state, связанной с проектом и аккаунтом. Она не включается в переносимые резервные копии. Серверная версия определяет порядок; часы устройств не выбирают победителя.
- Трёхстороннее объединение выполняется по целым записям. После него проверяется полный граф связей, включая возвраты, платежи и покупки. Две разные правки одной строки требуют выбора; одинаковые правки не дублируются.
- Outbox принадлежит одному устройству и не передаётся. Подтверждается только состояние, которое не изменилось за время обмена. Потеря ответа не создаёт повторные финансовые операции: следующая проверка сопоставляет фактическую облачную версию.
- Восстановление из .mfin и смена аккаунта требуют явного выбора версии перед новым обменом. Откат серверной версии также останавливает автоматическое объединение.
- Все HTTP-запросы используют HTTPS, ограничение размера и времени; перенаправления с токенами отключены. Авторизация использует [Supabase Auth REST](https://github.com/supabase/auth/blob/master/openapi.yaml).

В этой версии по сети передаётся целая база, а не очередь отдельных записей. Это увеличивает трафик и время обмена; при больших вложениях требуется дождаться завершения. Рабочая локальная SQLite-база по-прежнему без собственного шифрования. Ограничения файлов и полного формата .mfin остаются прежними.

## Проверка перед личным использованием

На тестовом проекте проверьте отказ чтения/записи без входа, из другого аккаунта и прямой записи в таблицу; успешную запись через RPC; конфликт двух запросов с одинаковой версией. Затем перенесите вымышленные расходы и PDF между Android, Windows и Mac с выключенным домашним ПК. Убедитесь, что повтор после обрыва сети не создаёт дублей, а старые .mfin восстанавливаются с требованием повторного выбора версии. Эти реальные проверки ещё предстоят.
