# Финальный аудит Windows — ApriFinance 1.0

Дата: 15 ноября 2026. Проверяемая сборка: 1.0.0+19. Автор приложения: Bahadur.

## Результат

Заключение: локальный выпуск Windows готов к проверке владельцем и подготовлен к публикации. Критических и высоких открытых проблем в проверенных путях не обнаружено.

Проверены основные пути учёта, изменения и удаления записей, архивирование, планы и подтверждения оплат, резервные копии и восстановление, настройки анализа, обработка ошибок, Windows runner и NSIS. Ручное ревью сосредоточено на этих путях; полный набор автоматических тестов охватывает остальные модули. Это не доказательство отсутствия всех ошибок.

Сравнение выполнено с архивом исходников build 18. До подготовки публикации проект не имел Git-истории, поэтому git blame и анализ истории коммитов недоступны; исходной точкой служит сохранённый архив, его контрольная сумма сверяется с manifest предыдущего выпуска. Предыдущие артефакты не изменяются.

## Найденные и исправленные проблемы

| Уровень | Проблема | Исправление и доказательство |
|---|---|---|
| Средний | Обзор включал будущие операции в текущий остаток, анализ исключал их | Срез на сегодня; будущие операции применяются один раз в прогнозе своей даты. Регрессионный пример: остаток 900,00, будущие события дают 1 250,00 |
| Средний | Лимит на обзоре не учитывал подтверждённые алиасы и включал будущие расходы | Единая группировка категорий по политике, расходы только до сегодня; 80,00 по «Еда» учитываются в лимите «Продукты» |
| Средний | Будущая запись могла сделать счёт пригодным для архива при ненулевом текущем остатке | Проверяются текущий и полный остатки в той же транзакции; неудачная архивация не меняет базу и очередь |
| Средний | Большой агрегат денег мог переполнить 64-битное целое | Суммы через BigInt с проверкой конечного диапазона. Некорректный агрегат даёт понятную ошибку до передачи снимка интерфейсу; взаимно компенсирующие записи независимы от порядка |
| Средний | Сумма возвратов в импортируемом снимке могла переполниться и обойти проверку | Валидация сумм возвратов через BigInt; отдельный тест на 11 000 возвратов, рабочая база не меняется |
| Средний | Повторная ошибка чтения настроек могла быть скрыта расчётом по прежней политике | Ошибка чтения сохраняется, изменение настроек блокируется до успешного повторного чтения |
| Низкий | Изменение политики не всегда уведомляло обзор | ViewModel передаёт уведомления анализа; остатки кэшируются по снимку и дате, без повторного обхода каждой операции для каждого счёта |
| Низкий | Можно было открыть второй экземпляр и перезаписать настройки из другого окна | Именованный mutex; второй запуск активирует существующее окно и завершается до открытия базы. Отдельная debug-идентичность изолирует нативные тесты |
| Низкий | Скрипт упаковки принимал EXE с правильной версией, но старым номером сборки | Сверяются точный ProductVersion и время Dart payload относительно исходников |
| Низкий | Визуальные тесты зависели от текущего дня и незавершённой прокрутки | Фиксированная дата в данных эталонов и ожидание завершения прокрутки перед нажатием |

Критических и высоких проблем в проверенных путях не обнаружено. Все перечисленные находки исправлены; уровни отражают влияние на личный локальный учёт, а не оценку внешней эксплуатации.

## Проверка вариантов и затронутые вызовы

Поиск начат с `accountBalances`, затем расширен на `monthTotals`, `forecast30Days`, `budgetProgress`, прямые денежные агрегаты и вызывающие участки. Подтверждены варианты в обзоре, архивировании и проверке импортируемых возвратов. Использование полного баланса в исторических тестах и проверках истории сохранено намеренно; UI явно запрашивает текущий срез. Лимит суммы одной операции и диапазон агрегата — разные проверки.

Влияние: `accountBalances` вызывается ViewModel и проверкой архивных счетов, `monthTotals` — ViewModel и бюджетами, `forecast30Days` — обзором и проверкой загружаемого снимка. Контракты добавляют необязательную границу даты, старые исторические вызовы не меняются. Поведение UI при будущих операциях изменено явно: остаток и текущий факт считаются на сегодня, будущая запись остаётся в журнале и календарном прогнозе.

## Выполненные проверки

- **354 unit/widget-теста проходят** в рабочем проекте и в отдельной чистой копии для публикации; 11 новых проверок относительно build 18.
- Статический анализ: **No issues found**, проверка форматирования проходит.
- Пять нативных Windows-сценариев проходят, включая второй процесс и полный журнал с восстановлением. Устаревший селектор прокрутки нативного теста исправлен; для диагностики оставлены только названия этапов без финансовых данных.
- Release Windows собирается штатным скриптом из подготовленной копии, зависимости разрешаются с enforce-lockfile.
- NSIS 3.13: установка в отдельный каталог, миграция прежнего QA-пакета, повторное обновление, защита от старшего номера версии/сборки и работающего приложения, удаление с сохранением тестовых данных — **пройдены**.
- Все подготовленные к GitHub текстовые файлы проверены: личных путей, ключей, финансовых баз и дополнительных отметок авторства нет. Сторонние лицензии сохранены.
- Предыдущие выпуски сверяются по SHA-256; новые артефакты имеют отдельный manifest и контрольные суммы.

Нативные сценарии запускаются с отдельным mutex и временными SQLite. Настоящая база владельца не открывается. QA-установщик использует отдельную регистрацию, каталоги и ярлыки. Сверяются SHA-256 полезной нагрузки и сохранность фиктивных базы, PDF и зашифрованной копии при обновлении и удалении.

## Подготовка публикации

В отдельный каталог включаются исходники, тесты, закреплённые зависимости, инструкции, локальные скрипты проверок и сборки, сведения о сторонних лицензиях. Исключаются финансовые данные, резервные копии, ключи, сертификаты подписи, локальные настройки SDK, кэши, журналы, внутренние материалы и пути рабочей машины. История работы не переносится в публичную Git-историю. Коммиты и удалённый push не выполняются до выбора репозитория и идентичности автора.

## Ограничения выпуска

- Проверка Windows выполнена на текущей машине; отдельная чистая Windows без средств разработки не использовалась. Runtime DLL включены в пакет, их подписи Microsoft проверяются.
- EXE и установщик без подписи издателя. Системные уведомления Windows пока отключены.
- Синхронизация остаётся отложенной; реальное облако не проверено и не включалось. Финансовый обмен не отправляет локальные настройки анализа.
- Android и macOS не входят в этот финальный аудит. Код общих модулей обновлён, но новый APK и macOS-приложение здесь не выдаются как проверенный выпуск.
- Статистический прогноз условный: требования к полноте, проверка качества, ограничения горизонта и диапазона сохраняются. Наличие 90 правил не означает 90 постоянных сообщений.
