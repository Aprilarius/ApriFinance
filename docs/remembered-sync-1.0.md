# Подключение и хранение входа — сборка 21

В обычном интерфейсе остаются email, пароль аккаунта и однократное открытие копии её паролем. URL и публичный ключ заданы в сборке; другой проект настраивается отдельно. QR-подключение не входит в этот выпуск.

Сохраняются токены и пароль копии в системном защищённом хранилище. Пароль аккаунта не сохраняется. Запись проверяется повторным чтением. Обновлённый refresh token сохраняется до следующей операции с облаком; отказ записи останавливает операцию, новый токен остаётся в памяти для повторной попытки. Вход и пароль копии привязаны к проекту и ID пользователя. Смена владельца не переиспользует чужой пароль.

Выход сначала удаляет локальную сохранённую запись, затем завершает удалённую сессию этого устройства. Отзыв токена требует нового входа. Потеря или блокировка хранилища не удаляет SQLite; аварийное завершение во время записи системного хранилища может потребовать повторного входа. Сохраните пароль копии отдельно для новых устройств.

## Проверки

- Полный набор unit/widget-тестов; дополнительные тесты ротации и повторов, параллельных запросов, смены владельца, отказа хранилища, восстановления без сети и удаления сохранённого подключения.
- Регрессия: ошибка старого файла публичных настроек не создаёт скрытый новый сохранённый вход.
- Регрессия: новый конфликт требует нового подтверждения замены, даже если прежний чекбокс был выбран.
- Сценарий первого подключения, повторный запуск без повторного ввода и небольшой экран 320×568 с увеличенным текстом и клавиатурой.
- Нативная fixture-only проверка системного хранилища на Windows и macOS включена в workflow. Используется уникальная вымышленная запись, без чтения пользовательских секретов.
- Скан исходников и payload перед публикацией блокирует приватные файлы, административные ключи, JWT и сохранённые credentials. В журнал выводятся только путь и тип нарушения, без найденного значения. Это дополнительная проверка к проверенному составу файлов; не универсальная система распознавания любых личных данных.
- В реальном проекте подтверждены выключенная публичная регистрация и отказ анонимному чтению финансовой копии. RLS и RPC v2 проверены транзакционными SQL-сценариями предыдущего выпуска.

Точные результаты сборки доступны в [GitHub Actions](https://github.com/Aprilarius/ApriFinance/actions). Выпуск создаётся только после прохождения всех трёх платформ и проверок состава файлов. Приватный ключ подписи находится только во временном каталоге runner либо передаётся через приватные GitHub Secrets; в артефакты включаются только установщик, APK, Mac ZIP и контрольные суммы.

## Границы

Проверка на физических Android/Mac и обмен на трёх домашних устройствах остаются необходимыми. Android APK — release preview, без debug-доступа; при отсутствии постоянного приватного ключа CI использует временную подпись, поэтому замена прежней установки может требовать её удаления. Перед заменой сохраните .mfin и пароль. Mac — ad hoc подпись без нотарификации Apple; доступ к login Keychain может потребовать разрешение ОС. Windows EXE без подписи издателя. Локальная SQLite не получает дополнительного шифрования в этом обновлении.
